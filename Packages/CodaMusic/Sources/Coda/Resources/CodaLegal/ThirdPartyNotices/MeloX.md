# MeloX playback and lyrics synchronization

Source: https://github.com/youshen2/MeloX
Commit: `a41ea0e1e1fa69fb543d827b853fe3aff5420951`

The shared `AppleMusicLyricsColumn` uses the existing iOS adaptation of this revision's default Apple Music 26 typography. Primary lyrics use system bold at 36pt with 25pt row spacing and a 0.98 deselected scale. Wide viewports scale the font and row spacing together. Romanization has a 5pt gap above the primary lyric. Translation has a 7pt top gap and 4pt bottom padding. Supplemental text uses bold Title 3 or bold Callout when romanization is shown. macOS uses the corresponding iOS default sizes of 20pt and 16pt, and iOS uses its Dynamic Type metrics. These values adapt `AppleMusicLyricsTypographyProfile.swift`, `AppleMusicLyricsMotionProfile.swift`, `AppleMusicLyricsSupplementalTextProfile.swift`, and `AppleMusicLyricsView.swift`.

The playback-detail line-position cascade adapts `AppleMusicLyricsLinePositionPlanner.swift`, `AppleMusicLyricsDynamicSpring.swift`, and the focus movement in `AppleMusicLyricsView.swift` at `09713edb847a0f0a3515a34f779cc630d4fe5985` (GPL-3.0-only). On iOS, Coda uses the fixed and gap-dependent springs to animate the native iPadOS 16-compatible scroll view and applies stagger as a function of its measured scroll progress. On Mac, `DesktopLyricScrollTransition.swift` ports the corresponding desktop planner, the physical spring branch of `LyricMovementTransition.swift`, and the prepare/settle sequence in `DesktopLyricsScrollView.swift`. Coda applies preparation compensation from the current layout pass and retains its own row renderer, data source and focus anchor.

The files in `Sources/Coda/Core/Player/Lyrics/` retain the upstream parser, models, duet resolution, playback clock, focus timeline, cascade planner, character timing and highlight progress algorithms. The unused upstream accessibility-string helper is omitted in favor of Kumone’s existing accessibility representation. The timing attribute omits SwiftUI's iOS 18+ TextAttribute conformance to support iPadOS 16; its timing fields are unchanged. The text builder retains the timing functions and adapts their output to the existing Core Text host.

`LyricsCursor` adapts MeloX's NowPlayingLyricSynchronizer to Kumone's ObservableObject service and engine samples. Raw response parsing and per-frame highlighting delegate to these upstream algorithms. No song-specific or Bluetooth offsets are applied.

The NetEase lyric request profile and primary/legacy EAPI parameters follow `MeloX/Core/Networking/NeteaseAPI.swift` and `NeteaseDirectClient.swift`: mobile EAPI header, `e_r=false`, v1 word/translation/romanization versions set to zero, legacy `_nmclfl=1`, cancellation without fallback, and `pureMusic` decoding.

Playback history originally used that revision's EAPI `feedback/weblog` contract. Following reports of uploads not entering remote history, the transport now uses NCBL log files; see NeteasePlaybackLog.md. `PlaybackHistoryReporter` retains the adapted upstream submission sequencing, account checks and source capture (falling back to the album), with session fingerprints, finish deduplication and remote timestamp verification. Repeat-one and macOS AutoMix handovers start a new history session. General account and music requests use Kumone’s desktop EAPI profile and persistent installation identity; lyrics retain their separate mobile EAPI profile.

The karaoke preference follows MeloX: it changes timed rendering and the effective lead (0 for authored word timing, 0.2 seconds for line presentation). It does not swap YRC for an unrelated LRC row timeline. Both rendering modes use the same upstream parsed source and stable IDs.

Verification for NetEase song 142930 (齐秦《不让我的眼泪陪我过夜》): a separately compiled, unmodified upstream parser and timeline produced golden results at 0.05-second intervals through 273.2 seconds. The integrated cursor matched all 10,930 focus/active-line samples across karaoke enabled/disabled modes. The mobile EAPI endpoint was also queried successfully. These checks verify code and time-line parity; they do not substitute for listening to the physical iPad output.

The iOS playback layer integrates AudioStreaming 1.2.8, MeloX’s decoder and seek patches, and Kumone’s HTTP-byte observation hook under `Sources/Coda/Core/Player/Streaming`. `AudioPlaybackDeck` and `AudioPlaybackFormat` adapt the deck and source-format discovery. The deck reports decoded progress, buffering, and completion and supports muted seeks and rate changes. Coda supplies URL sources, volume, a per-track spectrum sink, and the playback queue and offline lifecycle. [AudioStreaming attribution](AudioStreaming.md) · [MIT license](AudioStreaming-LICENSE)

AudioStreaming’s existing HTTP requests now mirror original file bytes into `StreamingAudioCacheFile`, on a separate disk queue. The observer covers both normal stream chunks and the MP4 atom-fetch compatibility path before restructuring; it never issues requests. Byte ranges, total size and representation validators must remain consistent. Only complete files are promoted through the existing AudioCache format; gaps, cancellation, invalid responses, oversize files or cache clears prevent promotion. Existing cache entries and download leases remain usable. The former independent cache download has been removed.

`Scripts/test-streaming-playback.sh` compiles the streaming implementation and the iOS adapter for a muted host test run. It covers packet-accurate seeking, buffering, pause and resume, source replacement, HTTP range observation, and cache assembly and cancellation.

The playback-detail visual upgrade uses the existing `LyricLongToneEmphasis` and `LyricHighlightRevealProgress` algorithms for per-character reveal and long-note emphasis. `KaraokeGlyphRenderer` is a Kumone Core Text adapter: it caches the original shaped text into strips (keeping ruby/base groups together), then composites reveal, glow, rise and emphasis without changing row layout. The rise continuation and glow tail follow the behavior described by MeloX's `LyricGlowTextRenderer`; it does not require SwiftUI's iOS 18 TextRenderer. Reduced Motion keeps the reveal and disables rise, scale and glow.

The artwork-flow player background references MeloX's `DesktopAppleMusicBackdropShaders.metal`, `DesktopAppleMusicBackdropView.swift`, and `DesktopAppleMusicBackdropArtwork.swift` at the revision above: a diagonal-sized cover base, independently rotated cover layers, feathered edges, cached softened artwork and a crossfade between covers. Kumone's `NowPlayingFluidBackground.swift` implements a bounded native Metal surface for iPadOS 16/macOS, with its own analytic coordinate warp instead of MeloX's recovered pinch-mesh data. The Gaussian blur is prepared once per artwork on a worker. The low-frequency onset envelope drives a pronounced kick zoom and warp, plus a subtle flow-speed response; brightness follows the application's appearance rather than the player's always-dark controls. The MSL source is compiled as one shared pipeline, avoiding SwiftUI's newer layer-effect API and per-frame full-resolution blur. This is an adaptation of the visual approach, not a pixel-identical reconstruction of MeloX.

To avoid blocking player entrance and exit, the shared Metal pipeline is prepared asynchronously and warmed when the iOS root appears. A plain CAMetalLayer replaces main-thread MTKView draws: drawable acquisition and frame encoding run on a serial worker with one pending frame at most, and unchanged drawable dimensions are left alone. A bounded four-entry texture cache coalesces concurrent artwork preparation and reuses textures across player presentations.

QQ Music word timing uses MeloX’s `QQMusicLyricDecoder`, `QQMusicModifiedDES`, and `QRCLyricNormalizer` at the same revision, with Swift 5 compatibility. The QQ request profile requests encrypted QRC first and retains a separate line timeline for translation alignment. Base64 LRC and legacy web responses remain supported by Kumone’s provider adapter.

Portrait lyrics interface behavior adapts `LyricsScrollInterfaceVisibilityTracker.swift`, `AppleMusicLyricsView.swift`, `NowPlayingView.swift`, `NowPlayingBottomControls.swift`, and `NowPlayingMotionSpec.swift` at the revision above. `LyricsScrollInterfaceVisibilityTracker` retains the upstream accumulation/direction algorithm and default 200pt threshold. An iOS 16 UIKit adapter observes normalized scroll offsets during dragging and inertia, excluding automatic following and rubber-banding. The iPhone and iPad portrait player uses layered controls over a stable lyrics viewport, reverse-scroll and tap restoration, and automatic hiding after **3 seconds** (the requested override of MeloX's 5-second default). VoiceOver prevents automatic/manual hiding; Reduced Motion removes motion. Tablet portrait deliberately shares this behavior, whereas upstream's tablet layout opts out.

The iPhone playlist header directly adapts `StandardMusicCollectionDetailHero`, `MusicCollectionPrimaryActions`, and `MusicCollectionArtworkBackdrop` from `MeloX/Features/Playlist/PlaylistDetailContent.swift` at commit `9c2f87b57b54ddbab76a4a53736f4840719a0947` (GPL-3.0-only). `PlaylistDetailHero.swift` preserves the upstream centered artwork (68% width, capped at 300pt), title/subtitle/metadata typography and spacing, three-button arrangement, and backdrop overlay. Adaptations add a creator avatar, replace shuffle with subscription and the trailing save button with Kumone's menu, use Kumone's existing playback/subscription services, and provide iOS 16-compatible geometry, cached artwork and glass material fallbacks. The iPhone navigation bar retains only the native back control. The search field and song list retain Kumone's implementations; iPad and macOS retain their existing layouts.

The iPhone daily recommendations page shares `PlaylistHeader`, `PlaylistPrimaryActions`, and `PlaylistArtworkBackdrop` with playlists, including the search field, hero geometry, overflow control, and transparent song panels. Daily recommendations omit subscription and retain the daily playback/recommendation context and daily update metadata.

The iPhone artist page also reuses the same hero, primary action row and artwork backdrop. Artist-specific adaptations retain a circular portrait, show aliases and song/album counts, and bind the three controls to artist follow, popular-song playback and the existing overflow menu. The popular tracks and album/EP/similar-artist shelves retain horizontal scrolling.

The iOS playlist and artist backgrounds now adapt `ArtworkAccentColorProvider.swift` and `MusicCollectionArtworkBackdrop` at `9c2f87b57b54ddbab76a4a53736f4840719a0947` in `DetailArtworkBackground.swift`: 160px Lanczos preparation, Core Image area-average RGB, the upstream 0.52 weighted-brightness threshold, dark/light background mixing, radius-18 clamped Gaussian blur, 0.22 texture opacity and matching overlay stops. The resulting palette drives page and toolbar appearance on iPhone without changing header layouts. iPad keeps its theme background and does not load artwork palettes. A bounded actor-owned NSCache retains prepared assets; reduced motion disables the 0.18-second update animation. Other consumers of the shared artwork backdrop also receive the updated rendering.

Cloud upload flow references `MeloX/Core/Cloud/CloudUploadFile.swift`, `CloudMusicModels.swift`, and `Core/Networking/NeteaseAPI.swift` / `NeteaseDirectClient.swift` at `9c2f87b57b54ddbab76a4a53736f4840719a0947` (GPL-3.0-only). Kumone adapts the upload check, separate metadata/NOS tokens, streamed transfer, registration and publication flow to its existing client, adding temporary file snapshots, login binding, native file import and cloud deletion confirmation.

Single-column artwork/lyrics transitions adapt `MeloX/Features/Player/NowPlaying/NowPlayingMotionSpec.swift`, `NowPlayingView.swift`, `NowPlayingPageTransition.swift`, `NowPlayingPortraitArtwork.swift`, `NowPlayingArtworkPage.swift` and the lyric-readiness coordination at `09713edb847a0f0a3515a34f779cc630d4fe5985` (GPL-3.0-only). `NowPlayingPortraitArtwork` retains the shared overlay, 12pt corner radius, playback-dependent artwork-page shadow (none on the 72pt lyric header), and playback/artwork-page entry bounce (1.055 scale over 0.17s, then a 0.42s spring with 0.24 bounce). The default paused artwork-page scale is 0.74; the lyric header remains 72pt. No additional interface mode or pause-size preference is introduced.

Page selection uses MeloX's 0.30s smooth animation, separately from the 0.48s playback/pause resize. The hidden stationary artwork-page measurement provides the large-cover destination frame while the visible details move by -300pt using 0.22s/0.07s incoming and 0.24s outgoing timing. The song header uses 40pt travel, 0.40s/0.08s incoming and 0.24s outgoing timing. Lyrics retain the 1/350/40/0 spatial spring, 0.90 hidden scale and 0.18s (0.42, 0, 0.58, 1) opacity curve. Initial lyric focus readiness gates entry at 0.07s, with a 0.35s fallback; an exit reversed within its opacity interval resumes immediately. The resident Core Text lyrics and existing controls remain in place. This adapter uses SwiftUI's interruptible resident-layer animations rather than importing MeloX's full queue transition coordinator.

Kumone retains its responsive content bounds, cached artwork loader, album actions and controls. The feature applies to single-column iPhone/iPad layouts, including iPad portrait widths above 600pt. iPadOS 16 substitutes response/damping springs for unavailable smooth and duration/bounce APIs; those fallbacks are approximations. macOS and two-column player layouts keep their existing artwork behavior.
