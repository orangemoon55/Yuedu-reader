# 三平台统一音质与码率显示

更新时间：2026-10-30。

## 产品规则

网易云、QQ 音乐、酷狗共用四档名称，不显示编码格式作为选项名称。详情页音质按钮只显示档位文字，例如“高品质”“高解析度无损”；点击展开的二级音质菜单才显示码率，下面表格的示例均指菜单选项：

| 档位 | 资源判定 | 示例 |
|---|---|---|
| 标准 | 平台标准有损资源，通常约 128 kbps 或以下 | 标准 · 128 kbps |
| 高品质 | 平台较高/高品质有损资源，通常为 192 或 320 kbps | 高品质 · 320 kbps |
| 无损 | 接口确认的无损资源 | 无损 · 905 kbps |
| 高解析度无损 | 无损资源且确认位深 >16 bit 或采样率 >48 kHz，或平台明确返回高解析资源档位 | 高解析度无损 · 1608 kbps |

档位依据资源属性和平台协议，不用无损码率阈值划分。1714 kbps 的资源不能仅凭码率自动升级为高解析度无损。编码格式仅参与内部判定，不出现在音质名称里。

内部保留原请求键，兼容已保存的偏好与缓存；`higher` 和 `exhigh` 均显示“高品质”。同一歌曲同时具备 192 和 320 档时，只提供 320 档；只有 192 档时仍可选择高品质。特殊音效档位不作为这四个基础档位的同义词，统一菜单不列出。

## 码率来源

- **网易云**：歌曲详情资源的 `br`，单位 bps，除以 1000 显示 kbps。菜单使用当前歌曲的资源值，不以固定无损码率代替。
- **酷狗**：实际播放解析结果中的 `bitRate` / `bitrate` / `bit_rate`。兼容以 kbps 返回的低位数值。以返回文件的实际档位与码率生成名称，不能使用请求的 `quality` 冒充实际结果。高解析位深、采样率缺失时，可读取音频文件头核验。
- **QQ 音乐**：当前详情接口未提供直接数值码率。使用 `track_info.file` 中对应文件大小与 `track_info.interval` 计算平均码率：`bytes × 8 ÷ durationSeconds`。`M500` 对应 `size_128mp3`，`M800` 对应 `size_320mp3`，`F000` 对应 `size_flac`，`RS01` 对应 `size_hires`。计算结果一律显示“约”，不再把 M500/M800 标识映射成伪装为接口实测值的固定 128/320 数字。此接口的资源大小不等于账号一定能获得该资源授权，菜单仍结合播放解析结果去重。

三个平台共用文件大小与时长的估算回退：优先直接码率，缺失时才计算平均码率并标注“约”。网易云使用资源 `size` 与歌曲 `dt / 1000`；酷狗使用同一播放响应的 `fileSize` 与 `timeLength`（秒）；QQ 使用前述文件大小与时长。严禁使用另一档位的文件大小或时长。

数值最多保留一位小数，删除末尾 `.0`。例如 `935088 bps` 显示 `935.1 kbps`，`128001 bps` 显示 `128 kbps`。整数秒时长与文件封装开销会影响 QQ 的估算结果。

## 缺失值与播放行为

- 没有有效直接码率且无法通过文件大小、时长估算时，只显示档位，例如“高解析度无损”。不显示格式名、零码率或编造的固定值。
- QQ 详情请求失败时，仍保留已确认可播放的档位，但不补写估算码率。
- 酷狗旧数据中的重复 hash 不能构成多个音质；先补全歌曲元数据，并以真实解析结果去重。
- 服务端降级后，播放器继续按照实际返回的档位显示，而非所选偏好。详情页当前音质标识只显示实际档位文字，码率仅出现在展开后的菜单中。
- “总是最高”在四个基础档位中选择可播放的最高档。无损/高解析请求降级到标准后，仍继续检查高品质资源，避免漏掉 320 档。
- QQ 现有播放适配器的高解析请求仍可能命中 F000 无损资源；不能因为请求了高解析就生成高解析度无损选项。只有实际资源被适配器确认为高解析档时才显示该档位。

## 实测依据

2026-10-30 对三个平台各检查 8 首歌曲：网易云无损约 798–986 kbps，高解析约 1677–2832 kbps；QQ 无损资源平均码率约 929–1714 kbps；酷狗有些无损/高解析资源直接返回码率，有些缺失。范围仅描述本批样本，不是产品判定阈值。

## 最高音质偏好的保存

“总是最高”是持久偏好，与当前实际播放档位分开：选项通过勾选状态显示是否启用；即使当前只能播放标准音质，该偏好仍保留。选择具体档位才退出自动最高。偏好写入 `settings.alwaysHighestAudioQuality`，启动时恢复，并与具体音质偏好一同参与跨设备同步。尚未包含该字段的旧同步记录不会清除本机选择。

## 切歌首次解析

队列可能保留较早的酷狗歌曲 ID 与仅有标准/高品质的 hash。请求无损或高解析时，如果对应 hash 尚未补全，必须先查找匹配歌曲并更新元数据，再开始音频解析，不能依赖打开音质菜单后才刷新。对同一来源、主 hash、标题、歌手和专辑的歌曲，队列恢复和列表注册不会覆盖已有更完整的音质元数据。当前《跃》的旧音频 ID 与新版搜索 ID 不同，已作为回归场景覆盖。
