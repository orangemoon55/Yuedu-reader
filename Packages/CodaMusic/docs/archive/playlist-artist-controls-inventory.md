# 歌单与歌手页面控件清单及 iPhone / iPad 统一准备

整理日期：2026-10-26。

以下清单保留首次整理时的代码基线，包括当时尚未提交的修改。整理采用静态阅读与调用关系核对，未做运行时截图验收。

后续实施记录（同日）：已将 iPad 歌单与共享音乐库页的搜索框移到封面头部上方；歌单与歌手页复用 iPhone 的圆形收藏/关注、黑白播放胶囊和圆形更多按钮。右侧信息栏与封面底部对齐，按钮之间也采用底部对齐；可用宽度不足480pt时将操作栏放到封面下方。iPad“我喜欢的音乐”的心动入口随 iPhone 放入更多菜单，并使用 Lucide `heart-pulse` SVG。最近播放、云盘、下载和每日推荐的共享头部同步采用搜索与操作栏样式；专辑详情和账户页不在本轮修改范围。

验证：真机与模拟器 Debug 构建通过，开发版 `sb.moe.kumone.dev` 已成功覆盖安装到约定的 iPhone、iPad，以及当时已启动的 iPhone 14 Pro（iOS 16.4）模拟器；未启动应用、真机自动化或测试 Runner，视觉效果仍需打开应用后验收。

## 最新实施：专辑接入、爱心复用与等高操作栏

已将设备适配集中到 `MeloXPlaylistHeader / MeloXPlaylistDetailHero` 内：iPhone 使用居中头部，iPad 使用共用的左封面/右信息布局与顶部搜索框。专辑、歌单、歌手、每日推荐，以及通过 `MusicLibraryHeader` 展示的最近播放、云盘、下载和保存集合都接入这一条路径。旧的独立音乐头部仅保留在 macOS 编译分支，不再作为 iPad 的备用样式；账户快捷操作和收藏类型选择器保持各自的业务控件。

- 三个头部按钮共用 `MeloXPlaylistActionMetrics.height = 56`，收藏/关注、播放、更多全部等高并底部对齐。
- 专辑的搜索输入、结果列表和播放按钮都使用筛选后的歌曲，iPad 也生效；更多菜单共用查看歌手、简介和下载操作。
- 歌曲行仅复用 `PlayerHeartIcon` 显示18pt已喜欢状态，与播放控制栏使用同一组爱心资源和红色。它是展示图标，没有点击、悬停或按压交互；未喜欢时隐藏并退出无障碍访问。喜欢操作仍在歌曲菜单及播放控制栏中。
- 歌曲行及纵向/横向列表容器统一透明；删除悬停底色、交替底色、当前歌曲底色和批量选择底色，选择状态仍通过勾选图标表示。间距、分隔线及加载骨架保持原有结构，页面背景可直接透出。
- iPad 侧栏“账户”的实际入口是 `SidebarDestinationView.account → AccountDetailsView`，不是 iPhone 标签页中的 `IOSLibraryView`。账户头部现由 `ProfileDetailHeader → MusicLibraryHeaderLayout` 复用圆头像、响应式几何和底部对齐；操作使用 `MeloXPlaylistPrimaryActions` 的56pt云盘、播放排行、更多，签名、用户ID、统计及失败重试保留。未登录头部同样复用标准组件。`IOSLibraryView` 的备用平板头部也同步使用共用操作栏。
- 下文的原始差异表是修改前的基线，不代表本轮修改后的现状。

## 1. 当前结论

- iPhone 歌单与歌手详情已共用 `MeloXPlaylistPrimaryActions`：左侧收藏/关注、中央播放、右侧更多。
- iPad 的对应操作仍分别写在页面里，采用 `MusicLibraryHeaderLayout`、44pt 文字胶囊按钮和无背景更多图标。现状是两套控件表达，不只是响应式位置变化。
- 歌曲行在所有 iOS 设备上都走 `TrackRow.isCompact == true`，已共享字号、封面、时长和行内动作；需要统一的主要是头部、菜单、弹层和状态，而非另做一套 iPad 歌曲行。
- 容器仍存在合理的响应式差异：歌单宽屏双列、歌手热门歌曲横向栏目、iPad 侧栏。统一控件不要求把这些内容布局全部改成一样。
- 建议沿用目前 iPhone 的控件语言作为统一起点，再抽出跨设备组件；具体尺寸和排列规则属于下文建议，尚未实施。

## 2. 页面覆盖

| 页面 / 状态 | 当前实现与需要覆盖的控件 |
| --- | --- |
| 普通歌单、收藏歌单、排行榜中打开的歌单 | `PlaylistDetailView`：搜索、播放、收藏、更多、简介、排序、整单下载、歌曲行和长按菜单 |
| 自建歌单 | 同一页面；iPhone 保留已收藏但不可操作的按钮，iPad 不显示收藏按钮；歌曲菜单可删除歌曲 |
| 我喜欢的音乐 | 同一页面，通过 `isLikedList` / `specialType` 判断；心动入口、隐藏行内喜欢按钮、特殊封面/元信息 |
| 雷达歌单 | 同一页面，传入 `.radar` 推荐上下文；当前 iOS 歌曲菜单不显示“减少推荐”，该项受 macOS 编译分支限制 |
| 歌手详情 | `ArtistDetailView`：播放热门歌曲、关注、更多、整组下载、四类栏目入口及卡片 |
| 歌手的热门单曲 / 专辑 / EP 与单曲 / 相似歌手子页 | `ArtistSectionView`：返回、歌曲列表或卡片网格、加载更多、错误重试 |
| 已下载中保存的歌单集合 | `DownloadedMusicView(collectionID:)`，不是在线歌单详情；搜索、排序、播放、下载任务、选择/全选/移除/完成 |

以下页面也复用同一批组件，后续抽取时须检查影响：专辑详情、每日推荐、最近播放、音乐云盘、已下载、“我的”账户页。独立“我的收藏”页仍使用旧头部与“专辑 / 歌手”分段选择器；它不是歌手详情内的控件。

## 3. 头部与页面边缘控件

| 控件 | iPhone 现状 | iPad 现状 | 统一关注点 |
| --- | --- | --- | --- |
| 返回 / 页面导航 | 详情由导航栈管理，使用系统导航行为 | 侧栏 + 详情导航栈，侧栏显隐和返回由宿主管理 | 作为导航层控件处理，避免各详情页重复添加返回按钮；实际显隐待运行时核对 |
| 侧栏 / 标签导航 | 首页、精选、我的、搜索等由外层标签导航提供 | `SidebarView` 提供音乐库/歌单导航，顶部设置按钮44×44pt | 属于全局导航；可共用图标规范，不要求两端采用同一种导航容器 |
| 底部迷你播放器 | `IOSMiniPlayerBar` 提供曲目信息入口、播放/暂停；非 inline 形态另有上一首/下一首 | iOS 外层播放器由同一宿主管理，随展示空间采用相应形态 | 这些是全局播放控件，不是歌单/歌手自己的操作栏；统一时核对遮挡与底部留白，保持当前单一播放器界面 |
| 歌单内搜索 | 封面上方常驻；44pt 高玻璃胶囊、前置放大镜，外侧水平间距20pt | 头部操作栏内常驻；44pt 高、圆角10pt、低对比填充，末尾额外搜索按钮28×44pt | 输入框本体都用 `PlaylistInlineSearchField`；应统一外壳、图标位置、清除和焦点反馈 |
| 歌手页搜索 | 无 | 无 | 内容差异；本次不把新增搜索作为样式统一的前提 |
| 播放 | 高50pt，最小宽116pt，`.title3.bold`；浅色黑底白字、深色白底黑字 | 高44pt，16pt semibold（由父容器设置），`Theme.LikedMusic.playButton` 红底白字 | 统一高度、色彩语义、字体、按压/禁用反馈；允许随空间调整宽度 |
| 收藏歌单 / 关注歌手 | 左侧56×56pt玻璃圆按钮；未选中为 `CollectionStar` 资源，选中为勾；无可见文字 | 高44pt文字胶囊，图标 + 收藏/已收藏或关注/已关注 | 统一图标、选中态、未登录态、请求中状态及可访问名称 |
| 更多 | 右侧56×56pt玻璃圆按钮，`.title2.semibold`省略号 | 44×44pt、22pt medium省略号，无显式背景 | 同一图形、底材、字号和点击区域；菜单内容仍按页面提供 |
| 心动 | 我喜欢的音乐的更多菜单内，空列表禁用 | 我喜欢的音乐头部独立文字胶囊；未显式绑定空列表禁用 | 统一入口层级及禁用规则；它是播放行为，不是新的播放器界面模式 |
| 歌单简介入口 | 更多菜单中的“歌单简介” | 元信息下方的简介文本可点击 | 统一入口命名和展开反馈；位置可以随布局变化 |
| 创作者头像 / 昵称、歌手别名、数量、播放次数 | 展示信息 | 展示信息 | 目前不是跳转按钮，勿当成已有交互；标题及简介文本样式单独管理 |
| 封面 / 歌手头像 | 居中封面，宽度为可用宽的68%，最高300pt；歌手为圆形 | 左侧封面/头像；窄布局112–200pt，宽布局200–240pt | 属于响应式展示；方形/圆形表达内容类型，无需统一成一种形状 |

按压反馈也不同：iPhone 共用操作栏设置 `.buttonStyle(.plain)`；iPad 头部容器设置 `.pressable`（缩放、透明度及动画）。统一按钮外壳时应一并收敛反馈。

### 按钮显隐与状态矩阵

| 场景 | iPhone | iPad | 后续应明确的规则 |
| --- | --- | --- | --- |
| 未登录，普通歌单 | 收藏按钮可见但禁用 | 收藏按钮隐藏 | 两端采用同一显隐策略 |
| 自建歌单 / 我喜欢的音乐 | 收藏按钮显示选中且禁用，沿用“取消收藏歌单”的可访问名称 | 不显示收藏；我喜欢的音乐另有心动按钮 | 不可取消的拥有状态应有准确名称；是否保留占位须统一 |
| 收藏请求中 | 收藏按钮禁用；没有独立加载指示器 | 回调以 `isSubscribing` 防重入，但按钮没有绑定该禁用状态 | 统一可见的请求中反馈和交互状态 |
| 未登录，歌手 | 关注按钮可见但禁用 | 关注按钮隐藏 | 与歌单的登录策略一致 |
| 歌手关注状态读取中 / 更新中 | 关注按钮禁用 | 关注按钮禁用 | 已共用业务状态，统一视觉反馈即可 |
| 没有可播放歌曲 | 播放禁用 | 播放禁用 | 保持禁用语义与外观一致；歌单使用 `playable`，歌手按热门歌曲非空判断 |

## 4. 更多菜单与排序

| 位置 | 当前项目 | 条件 / 差异 |
| --- | --- | --- |
| 歌单更多 | 歌单简介 → 心动 → 排序方式子菜单 → 下载相关动作 | 简介仅在有内容的 iPhone 页出现；心动仅在 iPhone“我喜欢的音乐”出现；iPad 两者在头部 |
| 歌单排序 | 添加时间由新到旧、由旧到新、歌曲名、专辑名、歌手名 | 共用 `PlaylistTrackSort`；前两项保留/反转接口原始顺序，不是根据歌曲 ID 排序 |
| 歌手更多 | 热门歌曲的下载相关动作 | 目前没有简介、搜索、排序、分享或举报项目；不要当成已实现控件 |
| 整组下载主动作 | 下载全部 / 停止下载 / 继续下载 / 移除歌单下载 | 随任务、完成和可恢复状态切换；歌单未完整载入时受 `canDownloadAll` 限制 |
| 整组下载辅助动作 | 暂停下载、停止下载、移除已有下载 | 按状态加入菜单；由 `DownloadCollectionButton(menuPresentation: true)` 统一提供 |
| 歌手下载文案 | 复用整组下载组件 | `owner` 为 `artist:`，但移除文案只区分 `album:` 与其他类型，因此会出现“移除此歌单…”；应改为按内容类型命名 |

下载动作包含登录入口、移动网络确认及移除确认，不应只迁移一个图标。歌单、歌手的整组下载都在更多菜单中；`PlaylistDetailView.downloadButton` 是未被当前页面调用的帮助方法，不计为现有独立按钮。

## 5. 歌曲行与行边动作

`MusicTrackPanel → TrackListView → TrackRow` 是歌单、歌手及其歌曲子页的共用链路。

| 控件 / 交互 | 当前实现 | 统一关注点 |
| --- | --- | --- |
| 点整行播放 | iOS 单击歌曲行开始播放；行背景有完整内容形状 | 保持整行和内嵌按钮的事件边界，避免下载/喜欢被误识别为播放；运行时待验 |
| 点封面播放 | iOS 封面为单独播放按钮；基础48×48pt，随字号缩放 | 已共用，不另造平板版本；与整行的不可播放/需联网反馈一起验收 |
| 下载状态按钮 | 24×24pt区域；基础下载图形16pt；iOS 初始隐藏，下载中、有任务、已下载或获得焦点时显示 | 点击区域建议扩到至少44×44pt；隐藏时已关闭命中与无障碍访问；维持列表列宽稳定 |
| 喜欢按钮 | 图形12pt；已喜欢或鼠标悬停时显示，否则 `opacity(0)`；没有相同的命中/无障碍隐藏处理 | 统一触控设备的可发现性；核查透明但仍可响应的按钮，不能沿用桌面悬停逻辑作为触屏主要入口 |
| 喜欢按钮覆盖范围 | 普通歌单传入 `showsLikeButton: true`；我喜欢的音乐隐藏；歌手热门及子页沿用面板默认 `false` | 是页面语义差异；是否始终展示需统一约定，保留菜单内喜欢操作 |
| 时长 / 正在播放 | 36pt宽时长槽，当前歌曲替换为播放指示器 | 展示状态，不是暂停按钮；两端已共享 |
| 歌手名 / 专辑副标题 | iOS 显示为文本；当前面板使用“歌手 - 专辑”副标题 | 当前不是文字跳转按钮；跳转在长按菜单中 |
| 歌曲长按菜单 | 播放、下载相关项、下一首播放、添加/移出我喜欢、收藏到歌单、删除、查看专辑、查看歌手、复制链接 | 两端共用；删除仅自己的歌单提供；歌手跳转最多列出3位有效歌手；是否补可见更多入口属于交互改进建议 |
| 单曲下载状态菜单 | 下载、暂停、取消、继续、移除下载 | `TrackDownloadActions` 与行内 `TrackDownloadButton` 存在文案/确认差异；行内移除弹确认，歌曲长按菜单的移除直接执行 |

基础行高64pt、封面48pt，通过 `@ScaledMetric` 随字号变化。iOS 不因 iPad 屏幕宽而恢复桌面专辑列、桌面序号或桌面字号。

## 6. 歌手栏目入口和卡片

| 控件 | 当前实现 | 统一关注点 |

| 专辑 / EP 卡片 | `NavigationLink + CoverCardBody + .interactiveCard` | 整张卡片跳转专辑；歌手页没有传 `onPlay`，因此没有封面悬浮播放按钮 |

| 加载更多 | 子页底部全宽、至少44pt高按钮；加载时换进度指示 | 共用标准加载/禁用/错误反馈；专辑与单曲分页，热门歌曲/相似歌手一次载入 |

## 7. 弹层与反馈

| 入口 | 当前表现 | 统一关注点 |
| --- | --- | --- |
| iPhone 歌单简介 | 滚动内容 sheet，medium / large 两档；未提供显式完成按钮 | 与专辑简介统一标题、边距、关闭按钮和展示策略 |
| iPad 歌单简介 | 头部文本弹 popover，正文14pt、最大宽380pt、高400pt | 展示容器可因空间自适应，内部阅读控件和关闭语义一致 |
| 收藏到歌单 | `AddToPlaylistSheet`：歌单条目、新建名称输入框、创建并收藏；外层固定宽340pt，列表固定高280pt | 改为可用宽度约束；补关闭入口、提交中反馈、防重复提交；大字号/窄窗待验 |
| 移除下载确认 | 单曲行内及整组下载使用 alert，提供移除/取消；整组提示其他歌单相同歌曲也会被移除 | 文案按单曲/歌单/歌手区分；确认策略保持一致 |
| 请求失败 / 成功反馈 | 收藏、关注、心动、删除、下载等使用 `ToastCenter`；失败由共享逻辑显示消息 | 保留反馈语义，避免迁移后仅改变图标无反馈 |
| 首次载入失败 | `ErrorStateView`：强调样式“重试”按钮 | 与刷新失败区分层级，复用同一组件 |
| 歌单部分载入失败 | 底部提示搜索可能不完整，普通 bordered“重试” | 明确属于局部恢复动作，避免第三套随意按钮规范 |
| 歌手刷新失败但已有内容 | 顶部 `PanelRefreshFailure` 材质条 + “重试” | 两端同一状态组件；核对与导航区的间距 |
| 空搜索结果 / 无内容 / 加载骨架 | 空结果说明、清空搜索、歌曲加载骨架等 | 不把非交互占位信息算作按钮；仅有真实恢复动作时展示可操作控件 |

## 8. 分支与存量代码注意事项

1. `usesMeloXHeader` 在歌单、歌手页按 `.phone` 判断，iPhone 横屏仍走手机头部，iPad 紧凑窗口仍走 iPad 头部。它与页面 `isCompact` 的“phone 或 compact size class”不是同一条件。
2. `MusicLibraryHeaderLayout` 还按实际内容宽度700pt切换宽/窄排列；列表也使用700pt阈值，但结合 size class，头部窄布局与列表单列不是简单同一个设备判断。
3. `TrackRow.isCompact` 对 iOS 恒为真；改头部时不要误以为歌曲行也有两套 iPhone/iPad 皮肤。
4. 歌单 `showSearch` 初始为 false；当前文件只有取消时写回 false，没有展开为 true 的入口。对应“搜索态替换头部 + UISearchBar + 取消”是存量分支，不能记为当前可达交互。`PlaylistSearchScrollGesture` 当前也仅有定义，没有挂载调用。
5. `ProfileDetailHeader` 虽存在于共享文件，但当前歌手详情使用的是 `MeloXPlaylistDetailHero / MusicLibraryHeaderLayout`，不是该旧组件。它另有账户页调用，不能直接全局删除。
6. `compatGlass` 在支持的编译器与 iOS 26 上使用玻璃效果，旧系统回退到 `.ultraThinMaterial`。记录中的 iPhone / iPad 系统版本不同，统一后仍应分别核对可读性与反馈，不要求跨系统像素一致。
7. 现有 `iphone-page-style-audit.md` 中“最近播放/云盘/下载左侧为排序动作”的描述与当前 `MusicLibraryHeader` 不一致：当前 iPhone 省略左侧按钮，把排序放在更多中。本清单以当前代码为准。

## 10. 实施顺序与验收准备

1. **优先统一头部控件**：抽出操作栏、主按钮、圆形按钮和搜索框，歌单/歌手两页同时接入；合并设备样式分支，布局继续按可用宽度响应。
2. **同步统一业务状态**：未登录、拥有歌单、已收藏/关注、读取中/提交中、空歌曲、心动可用性；确保按钮外观与实际可操作性一致。
3. **统一菜单与弹层**：排序位置、下载分组、歌手下载措辞、简介关闭、收藏到歌单尺寸与提交状态。
4. **补齐行内动作**：处理隐藏心形按钮的命中与无障碍语义、小点击区域、触屏可发现性；沿用已有歌曲行结构。
5. **复查共享调用页**：专辑、每日推荐、最近播放、云盘、下载与“我的”；下载选择态保留专门的批量操作语义。
6. **整理存量分支**：在确认无其他调用后清理旧搜索展开分支及未用帮助方法，不把死分支迁入新组件。

后续验收场景应覆盖：iPhone 竖/横屏；iPad 横/竖屏、侧栏开/关、窄窗口；深浅色；大字号与 VoiceOver；未登录、自建/他人歌单、我喜欢的音乐、雷达歌单、已关注/未关注歌手；空列表、离线、部分载入失败、下载中/暂停/完成。弹层打开、关闭及错误恢复均要覆盖。

本次未执行这些运行时验收。后续发生界面代码修改时，按 `AGENTS.md` 分别构建并覆盖安装到可用 iPhone、iPad 与已启动模拟器，保留数据、不启动应用；真机自动化另需用户明确授权。
